# Kuku's Cairo — Friendship Map Game: Build Spec for Claude Code

Nov 18, 2026 · @Ahmed

## Overview

Build a mobile-first, pixel-art web game where my best friend Kuku walks her own avatar around a cartoon map of Cairo and opens the photos and written memories from every place we've been together. It is a gift: it should feel personal, cozy and polished, not like a generic template.

**Core loop:** she sees the map → spots a place marker with a tiny photo preview → taps it (or steers there herself with a 360° joystick) → her avatar walks there → on arrival a memory window pops up with a photo slider and my written memory underneath.

**Hard requirements**

- Cartoon + pixel-art look throughout (map, landmarks, avatar, UI frames, fonts).
- Mobile web app opened from a single link; designed for phones in portrait, but must also work on tablets and desktop browsers.
- 10 places on a stylized Cairo map, each with a name, a pixel emblem, a photo-count bubble and a tiny thumbnail (like Snapchat's Snap Map memories).
- An avatar that looks like Kuku (fixed face, hair, glasses, skin tone) with basic outfit customization only.
- Two ways to travel: tap a place to auto-walk, or a circular 360° joystick for free movement.
- Memory window: horizontal swipeable slider (never photos stacked vertically), written memory below.
- All photos and memory text live in one easy-to-edit content file so I can fill it in without touching game code.
- Static site, deployable to a free host and shared as a link.

**Note to Claude Code:** read this whole document before writing code, then build in the phases listed at the end. The reference images mentioned in Art direction are in the `/references` folder; open and study them. Ask me before swapping any core technology choice.

## Tech stack and deployment

Use Vite + TypeScript + Phaser 3 for the game world, with plain HTML/CSS overlays for the UI windows, deployed as a static site to Vercel or Netlify.

| Concern | Choice | Why |
| --- | --- | --- |
| Build tool | Vite + TypeScript | Fast dev server, static output in `/dist` |
| Game engine | Phaser 3 (canvas/WebGL) | Sprites, tweens, camera follow, pinch/drag input, pixel-art mode |
| UI windows | HTML/CSS overlay above the canvas | Crisp text, native scrolling, easy swipe slider, accessible |
| Pixel rendering | `pixelArt: true`, `image-rendering: pixelated`, integer zoom steps | No blurry sprites on any screen |
| Font | "Press Start 2P" for titles, "VT323" or "Pixelify Sans" for body text (Google Fonts, self-hosted) | Pixel feel but readable memory text |
| Persistence | `localStorage` | Saves avatar outfit, visited places, settings |
| Hosting | Vercel or Netlify (free tier), auto-deploy from a GitHub repo | One shareable HTTPS link |

**Suggested structure**

```
/references          reference images (style, map, Kuku's photo) — not shipped
/public
  (originals live in /photos/<place-id>/ at the project root: never published, so GPS data stays private)
  /photos-optimized/    generated by script (webp, thumbs)
  /audio                optional music + sfx
/src
  /content/places.json  ALL places, photos, memories (the only file I edit)
  /game                 Phaser scenes: Boot, Map, (Avatar preview)
  /sprites              pixel-art sprite definitions / sheets
  /ui                   overlays: intro, wardrobe, memory viewer, HUD
  /lib                  pathfinding, storage, input helpers
/scripts/optimize-photos.ts   sharp-based image pipeline
```

**Deployment:** `npm run build` produces a static `/dist`. Add a short `DEPLOY.md` explaining how to push to GitHub and connect Vercel/Netlify, plus how to re-deploy after adding photos. Add `<meta name="robots" content="noindex">`.

## Art direction

The look is a cozy, warm, top-down 3/4-view pixel-art city, like a modern cozy sim: chunky outlines, soft shading, bright but not neon colors, lots of little life (trees, benches, birds, cars, people).

**Reference images (in `/references`)**

| File | What to take from it |
| --- | --- |
| `style-reference.png` | The target art style: 3/4 top-down pixel street scene, warm pastel palette, dark outlines, rounded trees, cobblestone, cars, scooters, café umbrellas |
| `cairo-map-reference.png` | The geography and vibe of the map: Nile running north–south in blue, districts as soft colored zones, landmarks drawn as little illustrated icons with labels |
| `kuku-reference.jpg` | What the avatar must look like (see Avatar section) |

**Palette and feel**

- Base: warm sand and beige for desert and streets, soft greens for parks, teal-blue Nile, terracotta and cream buildings, gold accents.
- Each district gets a soft tinted ground zone (like the reference map) so areas read at a glance.
- 1–2 px dark outline on all sprites; flat shading with one highlight and one shadow tone.
- Ambient life: animated Nile waves, a felucca sailing slowly, a few cars and tuk-tuks on roads, birds, swaying palm trees, twinkling lights at night mode (optional).
- UI windows: pixel 9-slice frames (cream paper with dark-brown border), chunky pixel buttons with a pressed state.

**How to produce the art (important)**

You cannot paint images, so create all pixel art in code: define each sprite as a small character grid plus a palette (e.g. 16×16 or 32×32), and turn the grids into textures at boot (Phaser `generateTexture` or a build script that writes PNG sprite sheets). Keep every sprite in its own file under `/src/sprites` so I can later replace any of them with a hand-drawn PNG of the same size without code changes. Free CC0 tiles (e.g. Kenney) are acceptable for ground textures only if they match the style; list anything you use in `CREDITS.md`.

## The map

The map is one large, hand-composed, stylized Cairo (not geographically exact) with the Nile through the middle, the 10 places in their roughly real relative positions, and Sahel as a beach zone at the top reached by a long desert highway.

**World setup**

- World size around 2400 × 3600 px at native pixel scale (portrait-friendly), drawn on a 16 px tile grid and shown at 2×–3× zoom.
- The Nile runs north–south through the middle, splitting around Zamalek island; bridges cross it (6th of October, Qasr El Nil style).
- Main roads connect every place; they double as walking paths (see Movement).
- Districts are soft tinted zones with small filler buildings, trees and props, so the map never looks empty between places.
- Desert edges in the west (near Zayed and the Pyramids) and east (past Tagamo3).
- Sahel sits at the very top: a strip of turquoise Mediterranean, white sand, umbrellas and white domed chalets, joined to Cairo by a winding desert road with a pixel road sign reading "Sahel ↑ North Coast". Visually separate it with a dashed edge or a small "far away" cloud band so it reads as outside Cairo.

**Rough layout (north up)**

```
  ~~~~~~~~ Mediterranean ~~~~~~~~
  [ SAHEL beach ]
        \
         \  desert highway (long)
          \
   ---------------------------------------- Cairo starts
                      |N|        [KUKU'S HOME]
```

## Place markers

Each place shows a small floating "memory bubble" above its emblem, like Snapchat's Snap Map memories: a tiny rounded photo preview plus a count badge.

- **Bubble:** a pixel-framed rounded square about 36–44 CSS px on phones, floating just above the emblem with a gentle 2–3 px bob animation.
- **Thumbnail:** a very small crop of the place's cover photo (`cover` in `places.json`, else the first photo), shown with a slight pixelation filter to match the art style.
- **Count badge:** a small circle on the bubble's corner, e.g. a camera icon and "12".
- **Name banner:** pixel ribbon under the emblem with the place name.
- **States:** unvisited (soft sparkle to invite a tap), visited (small checkmark or heart on the banner), selected (bubble scales up 1.2× with a pop).
- **Zoom behavior:** bubbles keep a constant on-screen size as the map zooms, so they stay tappable; when zoomed far out, hide thumbnails and show just the emblem and count.
- **Tap targets:** emblem, banner and bubble are all tappable, minimum 44 × 44 CSS px hit area.
- **Overlap:** Korba and Kuku's Home are close together; offset their bubbles so they never cover each other.

Bubbles and banners should be rendered so they stay crisp at any zoom (DOM overlay positioned from world coordinates, or Phaser objects with scroll-factor compensation).

## Avatar

The avatar is a chibi pixel version of Kuku whose face, hair, glasses and skin tone are locked to look like her; she can only change clothes and small accessories.

**Locked likeness (from `references/kuku-reference.jpg`)**

- **Hair, the signature feature:** big, voluminous, shoulder-length tight curls in very dark brown/black, forming a wide rounded cloud around the head. Exaggerate the volume in the sprite; the curly silhouette should be recognizable even at small size (use bumpy curl edges, not a smooth outline).
- **Glasses:** dark, thin rectangular-ish frames, always on.
- **Skin:** warm light-medium tan.
- **Face:** big warm smile, dark eyes, red-coral lips.
- **Proportions:** chibi, head about 40% of body height; sprite around 24×32 or 32×32 px. Also see `references/kuku-avatar-reference.jpg` (her cute cartoon avatar) for the cute, friendly feel.

**Default outfit (matches the photo):** white ribbed square-neck tank top with a small lace flower on one strap, dainty gold necklace with a small pendant, dark trousers, white sneakers.

**Customization (wardrobe screen)**

| Layer | Options (each with 3–6 color swatches) |
| --- | --- |
| Top | Default white tank, t-shirt, cozy hoodie, blouse, denim jacket over tank |
| Bottom | Jeans, wide-leg trousers, skirt, summer dress (replaces top + bottom) |
| Shoes | Sneakers, sandals, boots |
| Accessory | None, gold necklace (default), tote bag, sunglasses pushed up in the hair, flower clip |
| Seasonal (optional) | Beach outfit with sunhat that auto-suggests in Sahel |

- Build the sprite from stacked layers (body/face → bottom → top → shoes → accessory → hair → glasses) so any combination works and hair always draws on top.
- No skin, hair, face or glasses editing at all.
- Choices save to `localStorage` and can be changed any time from a wardrobe button on the HUD.
- Wardrobe screen shows a large live preview of the avatar (4–6× zoom) turning slowly, with left/right arrows per layer and a "Done" button.

**Animations:** idle (breathing, hair bounces slightly), walk cycle in 4 directions (4 frames each; left can mirror right), arrival celebration (small hop with a floating heart), and a soft shadow under her feet.

## Movement and controls

She can reach a place in two ways, and the memory window opens only when the avatar actually arrives.

**1. Tap to travel (auto-walk)**

- Tapping a place's emblem, banner or photo bubble sets it as the destination; a pixel flag or pulsing ring marks it.
- The avatar walks there along roads using a simple waypoint graph (nodes at intersections and bridges, A\* or Dijkstra), never across the Nile except on bridges.
- The camera smoothly follows the avatar.
- Long trips (Sahel, Zayed, Pyramids, Tagamo3 from far away): travel at a sped-up pace, or have the avatar hop into a little pink pixel car for the drive and hop out on arrival. Cap any trip at about 4–6 seconds so it never feels slow.
- A "Skip" button appears during long trips to jump straight to arrival.
- Tapping a different place mid-walk re-routes.

**2. Free roam (360° joystick)**

- A circular virtual joystick in the bottom-left corner (thumb-sized, about 110 CSS px, semi-transparent pixel ring with a knob).
- Drag in any direction for 360° analog movement; speed scales with how far the knob is pulled.
- Pick the walk animation (up, down, left, right) from the angle.
- Desktop: WASD / arrow keys also work, and the joystick can be dragged with the mouse.
- The avatar collides with water (except bridges) and the world edges, but can walk freely over ground otherwise.

**Arrival detection**

- Each place has an arrival radius (about 40–60 world px). Entering it triggers: avatar stops, celebration hop, a short sparkle, then the memory window opens.
- After closing the window she must leave the radius before it can trigger again (no instant re-open loop).
- Mark the place visited in `localStorage`.

**Camera and map navigation**

- One-finger drag pans the map (when not touching the joystick); pinch zooms between about 1× and 4× in integer-friendly steps; desktop uses the mouse wheel.
- A "recenter" HUD button snaps the camera back to the avatar.
- Optional mini "places list" button opens a scrollable list of all 10 places as a shortcut for tap-to-travel.

## Memory viewer

On arrival, a pixel-framed window pops up with a horizontal photo slider on top and my written memory underneath; photos are never stacked vertically.

**Layout (portrait phone, top to bottom)**

1. Header: place emblem, place name, optional date or "since" line (e.g. "Summer 2024"), close button (✕).
2. Photo slider, about 55–60% of the window height:
   - Swipe left/right with momentum and snap (touch and mouse drag); arrow buttons on the sides for desktop; keyboard ← →.
   - Dot indicators or "3 / 12" counter underneath.
   - Photos fit inside the frame (`object-fit: contain`) on a soft blurred or patterned backdrop so portrait and landscape photos both look good.
   - Optional short caption per photo, shown under the image.
   - Tap a photo for full-screen view (pinch-zoom allowed), tap again to return.
   - Supports short videos too if a file is `.mp4` (muted, tap to play) — nice to have.
3. Written memory: my text for this place in a readable pixel-style font (minimum 16 px), on cream "paper" with a scrollable area if long. Support line breaks and simple emphasis (a tiny subset of Markdown: paragraphs, **bold**, *italic*).

**Behavior**

- Opens with a playful pop-in (scale from 0.8 with a slight bounce) and a soft chime.
- Closes via ✕, tapping outside, swiping down, or Escape on desktop.
- Preload the first 2 full-size images when the avatar starts walking toward that place, lazy-load the rest.
- Whole window must fit within the viewport including safe areas (notch, home bar); on desktop it is a centered card at most about 480 px wide, or a two-column layout (slider left, memory right) on wide landscape screens.

## Content data model

Everything personal lives in `src/content/places.json` plus one photo folder per place, so I can add photos and memories without touching game code.

```json
{
  "friendName": "Kuku",
  "introMessage": "Welcome to our Cairo. Every place here is a little piece of us.",
  "places": [
    {
      "id": "zamalek",
      "name": "Zamalek",
      "area": "Island in the Nile",
      "position": { "x": 0.46, "y": 0.50 },
      "emblem": "zamalek",
      "date": "Since 2023",
      "cover": "zamalek-03.jpg",
      "photos": [
        { "file": "zamalek-01.jpg", "caption": "Our first felucca ride" },
        { "file": "zamalek-02.jpg" }
      ],
      "memory": "Write the memory here.\n\nNew paragraphs with blank lines. **Bold** and *italic* work."
    }
  ]
}
```

- Photos go in `photos/<place-id>/`. If `photos` is empty or missing, auto-list every image in that folder (via a build-time script that writes a manifest), sorted by filename.
- Photo count on the map bubble = number of photos for that place, computed automatically.
- Pre-fill `places.json` with all 10 places from the map table, placeholder memories ("Memory coming soon") and 2–3 colorful placeholder images per place, so the game works before I add real content.
- Validate the file at build time and print friendly errors (missing photo file, duplicate id, position out of range).

**Photo pipeline (`npm run photos`)**

- Uses `sharp` to turn originals in `photos/` into `public/photos-optimized/`: full size max 1600 px long edge as WebP (quality \~80), plus a 96 px thumbnail for map bubbles.
- Respects EXIF rotation and strips location metadata (GPS) for privacy.
- Runs automatically before `npm run build`.
- Add a `CONTENT-GUIDE.md` written for a non-developer: how to add photos, edit memories, change the cover photo, reorder photos, preview locally and re-deploy.

## Screens, devices and privacy

**Screen flow**

1. **Loading screen:** pixel progress bar with the avatar running in place.
2. **Secret question gate (optional, on by default):** a cute pixel lock asking a question only Kuku knows; answer set in `places.json` (case-insensitive, trimmed). Skippable in config.
3. **Title screen:** "Kuku's Cairo" (title text from config) over an animated pixel skyline with the Nile; a "Start" button; `introMessage` shown as a short typewriter-style note.
4. **Wardrobe (first visit only):** pick an outfit, then "Let's go". Later reachable from the HUD.
5. **Map:** avatar starts at Kuku's Home; a one-time tip bubble explains "Tap a place or use the joystick".
6. **Memory viewer:** as specified above.
7. **Finale (when all 10 places are visited):** a special pixel letter from me, text from `finaleMessage` in `places.json`, with confetti and fireworks over the Nile. Re-openable from the HUD afterwards.

**HUD (always on map):** progress "5 / 10 places", wardrobe, places list, recenter, sound on/off. Small pixel icon buttons, top corners, clear of the notch.

**Devices and responsiveness**

- Portrait phones first (test at 360 × 740 and 390 × 844); landscape phones, tablets and desktop must also work and look intentional.
- `viewport-fit=cover`, respect `env(safe-area-inset-*)`, use `100dvh`, disable double-tap zoom and pull-to-refresh on the game area, lock no orientation.
- All tap targets at least 44 × 44 CSS px; no hover-only interactions.
- Add a web app manifest and icons so she can "Add to Home Screen" and open it full-screen like an app.
- Sound off by default until her first tap (browser autoplay rules); soft lo-fi or chiptune loop plus small SFX for footsteps, pop and chime (optional; CC0 only).
- Respect `prefers-reduced-motion` (fewer bobbing and confetti effects).

**Performance targets**

- First load under about 3 MB before photos; photos load lazily per place.
- Smooth 60 fps on a mid-range Android phone; cap device pixel ratio for the canvas at 2.
- Static assets cached with long cache headers; photos as WebP.

**Privacy**

- The site is reachable by anyone with the link, so: `noindex` meta tag and `robots.txt` disallow, an unguessable deploy URL, GPS data stripped from photos.
- The secret question is a sweet gate, not real security (it runs in the browser). Say so in `DEPLOY.md`, and mention the host's password-protection option if I want real protection.
